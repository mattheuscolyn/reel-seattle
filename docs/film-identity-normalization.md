## 1. Executive summary

AMC and other sources often publish **special screening titles** (Sensory Friendly, Early Access, Opening Night Fan Event, IMAX events, anniversaries) as **separate film names**. Reel Seattle currently derives `showtime_film_key` from the **full display title**, so each variant becomes a distinct film identity.

This splits one underlying title into multiple keys across:

- `showtimes_current.json` film cards
- Planner search and schedule grouping
- Recently Added
- Leaving Soon weekly labels and footprint features

**Recommendation:** Treat identity normalization as a **prerequisite** before more Leaving Soon model tuning. Variant splitting inflates `normal_first_run` false positives and fragments lifecycle signals. Proceed in small PRs: audit (this doc) → persist AMC `movieId` forward → analysis-only parent keys → optional JSON/frontend grouping.

**AMC `movieId`:** Present in raw API payloads and now mapped in scrape logs (PR D5), but **zero historical backfill** in git-derived footprint CSV. Cannot unify legacy rows without re-scrape or new samples.

## 2. Current identity behavior

### 2.1 Key generation (title-only)

| Layer | Location | Behavior |
|-------|----------|----------|
| Slug function | `reel_seattle/normalize/titles.py` → `showtime_film_key()` | Kebab-case slug of normalized **full title**; optional `-YYYY` year suffix |
| History enrichment | `reel_seattle/history_keys.py` → `derive_showtime_film_key()` | `showtime_film_key(row["Film"])` — no variant stripping |
| Current emit | `reel_seattle/emit/current.py` | Groups films/showtimes by `showtime_film_key`; first-seen title wins in `films[]` |
| Leaving Soon emit | `reel_seattle/emit/leaving_soon.py` | Aggregates by `showtime_film_key` |
| AMC footprint | `reel_seattle/analysis/amc_footprint.py` | `showtime_film_key(record.title_raw)`; optional `amc_movie_id` from attributes |
| Frontend | `src/utils/plannerFilms.js`, `plannerEngine.js`, `showtimesPageEngine.js` | Film grouping keyed on `showtime_film_key` |

There is **no fuzzy matching**, cross-source TMDB unification, or parent-title logic in the production path. The module docstring in `titles.py` explicitly defers authority-backed `film_id` to a future phase.

### 2.2 Source IDs today

| Source | Stable film ID | Notes |
|--------|----------------|-------|
| **AMC** | `movieId` in API | Mapped in scrape logs (PR D5); **forward** into history CSV + `showtimes_current.json` as `source_film_id` (Identity-B). Legacy history blank. |
| **AMC** | `showtime.id` | Per-showtime only (`source_showtime_id`) |
| **Beacon** | None observed | Title-based keys |
| **SIFF** | None observed | Title-based keys; event phrasing in titles (e.g. Ghibli Fest) |

### 2.3 Special screening flags (analysis only)

`reel_seattle/analysis/special_screening_flags.py` (PR D4) classifies title patterns for Leaving Soon segments (`sensory_friendly`, `opening_night_like`, etc.). These flags **do not** change `showtime_film_key` or merge variants.

## 3. Observed variant splits (audit)

Generated by `python scripts/audit_film_variants.py` → `data/analysis/film_variant_audit.csv` and `film_variant_audit_summary.json` (gitignored).

### 3.1 Scale (2026-06-30 artifacts)

| Metric | Value |
|--------|-------|
| Current snapshot distinct `showtime_film_key` | 74 |
| Current variant-like keys | 6 |
| Historical footprint distinct keys (AMC git CSV) | 997 |
| Footprint rows with `amc_movie_id` | **0** (pre-D5 snapshots) |
| Parent groups with **multiple** film keys | **52** |

~5% of historical AMC title keys participate in a multi-key parent group under conservative suffix stripping. Impact is concentrated on wide releases with AMC event programming.

### 3.2 Representative parent / variant examples

| Parent | Variant titles | Notes |
|--------|----------------|-------|
| **Supergirl** | `Supergirl: Sensory Friendly Screening` | Live in current snapshot; separate cards |
| **Moana** | `MOANA IMAX Opening Night Fan Event` | Opening night overlaps parent release date |
| **Minions & Monsters** | `…: Sensory Friendly Screening` | Future-dated sensory showtimes |
| **Hoppers** | `Hoppers Early Access`, `Hoppers: Sensory Friendly Screening` | 3 keys; early access single-day |
| **Scream 7** | Opening Night Fan Event, Sensory Friendly | 3 keys across footprint |
| **The Fantastic Four: First Steps** | IMAX Opening Night, Sensory Friendly | Parent + 2 variants |
| **Citizen Kane** | `Citizen Kane 85th Anniversary` | Anniversary re-release (may be genuinely distinct programming) |
| **The Devil Wears Prada** | `…20th Anniversary Double Feature` | Double feature — **do not auto-collapse** with base title |

### 3.3 Leaving Soon impact

Weekly labels (`data/analysis/weekly_leaving_soon_labels.csv`) are keyed by `showtime_film_key`. Sensory and opening-night variants appear as **separate labeled rows**, often with:

- `run_type_segment = sensory_friendly` or `special_limited_run`
- Sparse footprint (`insufficient_current_showtimes`, `event_like_excluded`)
- Parent film continuing while variant row shows `leaving_soon=1`

Example: `fantastic-four-first-steps-sensory-friendly-screening` labeled separately from `fantastic-four-first-steps`. Parent normalization would roll footprint into one lifecycle curve.

### 3.4 Frontend impact (current snapshot)

Duplicate film cards when parent and variant are both in window:

- `supergirl` + `supergirl-sensory-friendly-screening`
- `moana` + `moana-imax-opening-night-fan-event`
- `minions-monsters` + `minions-monsters-sensory-friendly-screening`

Planner dedupes by `showtime_film_key`; searching "Supergirl" may not surface sensory showtimes under the parent card.

## 4. AMC `movieId` investigation

### 4.1 Raw payload

Fixture `tests/fixtures/adapters/amc_api_showtime_full.json` includes:

```json
"movieName": "New Future AMC",
"movieId": "movie-abc123"
```

### 4.2 Adapter persistence (PR D5)

`reel_seattle/adapters/amc_metadata.py` maps `movieId` → `attributes.movie_id` in daily scrape logs. Legacy adapter path without attributes leaves `movie_id` absent (`tests/adapters/test_amc.py`).

### 4.3 Same ID across variants?

**Not verified empirically** — historical git snapshots lack `movieId`. Hypothesis (high confidence): AMC uses one `movieId` per parent title; special screenings differ in `movieName` but share `movieId`. **Must confirm** with a small forward sample (see §4.5).

### 4.4 Historical backfill

**No.** `amc_film_footprint_from_git.csv` has `amc_movie_id` column but all values empty. Git-derived AMC JSON predates PR D5 mapping.

### 4.5 Safe forward collection (recommended)

Without live network calls in this pass:

1. Continue PR D5 mapping in scrape logs (done).
2. Add optional **redacted** fixture save: one showtime per distinct `movieName`/`movieId` pair per daily run → `data/analysis/amc_identity_samples/YYYY-MM-DD.jsonl` (gitignored).
3. After ~2 weeks of scrapes, run identity correlation audit: same `movieId` across variant titles?

### 4.6 Double features vs variants

`movieId` alone may **not** distinguish true double features (two films) from format variants. Title patterns (`double feature`, ` & ` marathon titles) and engagement metadata (if available via Movies API) should gate auto-merge.

## 5. Recommended parent / variant model

### 5.1 Proposed fields (future schema)

| Field | Purpose |
|-------|---------|
| `showtime_film_key` | **Keep** as stable per-source-title key (backward compatible) |
| `parent_film_key` | Slug of inferred parent display title |
| `parent_display_title` | Cleaned parent title for grouping |
| `source_title` | Exact theater-facing title (never discard) |
| `screening_title` | Variant portion if different from parent |
| `screening_variant_type` | `sensory_friendly`, `early_access`, `opening_night`, `fan_event`, `anniversary`, `double_feature`, `format_variant`, `none` |
| `format_tags` | IMAX, Dolby, 3D, Open Caption (already partially on showtimes) |
| `is_special_screening` | Boolean |
| `source_film_id` | AMC `movieId` when present |
| `variant_film_key` | Optional alias; default equals `showtime_film_key` today |

### 5.2 Grouping layer recommendation

| Stage | Use |
|-------|-----|
| **Adapter / normalization** | Capture `source_film_id`, preserve `source_title` |
| **Analysis / modeling** | **First** — compute `parent_film_key`, variant classification (`film_variant_audit.py`) |
| **JSON emit** | **Second** — additive fields on films/showtimes; do not rewrite `showtime_film_key` yet |
| **Frontend** | **Third** — group cards by `parent_film_key`, list variants under expander |

Safest path: **analysis-only parent keys first** so Leaving Soon and audits can validate before UI changes.

### 5.3 Merge rules (conservative)

**Merge under same parent when:**

- Suffix matches known screening patterns (sensory, early access, opening night, fan event)
- OR same AMC `movieId` with variant `movieName` (once verified)

**Do not auto-merge:**

- Double features with distinct program content
- Fathom / live sports / World Cup (`live_or_concert_like` segment)
- Genuinely different films sharing a franchise substring
- Anniversary re-releases when sold as standalone engagements (flag `anniversary`; human review)

## 6. Downstream impact & migration risk

| Area | Impact | Risk |
|------|--------|------|
| Historical CSV | Additive columns preferred (`parent_film_key`, `source_film_id`) | Low if optional |
| `showtimes_current.json` | Additive parent/variant fields | Low; keep existing keys |
| Planner search/grouping | Would improve dedup; needs parent-aware search | Medium |
| Recently Added | May double-count parent + variant as two "new" films | Medium |
| Leaving Soon labels | **High value** — unify footprint per parent | Medium; re-run label build |
| Film cards / posters | Fewer duplicate cards | Low–medium UI |
| Share URLs | Likely keyed on `showtime_film_key` today | Medium if URLs change |
| Title search | Must search parent + variant titles | Medium |
| Theater listings | Showtimes already per row; variant label on row | Low |
| Tests/fixtures | New audit tests; fixture with `movie_id` | Low |

**Do Identity-B/C before more Leaving Soon rule/ML tuning.** Variant splits fragment footprint, create sparse variant-only rows, and confuse `normal_first_run` vs `special_limited_run` segments. December stability issues may partially reflect title-identity noise rather than model capacity.

PR E (ship `leaving_soon_current.json`) and PR F/UI remain deferred per monthly stability gate.
